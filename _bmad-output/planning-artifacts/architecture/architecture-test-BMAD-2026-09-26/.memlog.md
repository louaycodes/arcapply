- (event) user selected coaching path
- (decision) System Topology: Decoupled architecture (Option B) separating Next.js UI cockpit from a local automation/backend engine/worker (scraping, LLM pipeline, browser automation)
- (decision) Stack & Runtimes: Frontend Next.js (App Router, Tailwind CSS, shadcn/ui, TypeScript) + Backend/Worker FastAPI (Python 3.12+, uv package manager, Pydantic, Playwright Python)
- (decision) Storage Ownership: SQLite database exclusively owned and mutated by the FastAPI backend via SQLModel/SQLAlchemy; Next.js accesses data strictly via backend API
- (decision) Communication Protocol: REST for commands, mutations, and CRUD; Server-Sent Events (SSE) for background task telemetry, scraper logs, and multi-stage LLM generation progress
- (decision) Anti-hallucination Invariant: 3-stage deterministic pipeline using Pydantic + instructor. Stage 1: Pydantic JobRequirements extraction. Stage 2: Pure deterministic Python matching against immutable MasterProfile JSON, isolating missing skills and strictly filtering context. Stage 3: Constrained generation with zero access to full master profile or unverified claims.
- (decision) LLM Provider: xAI Grok API (OpenAI-compatible client format via instructor with configurable api_key/base_url to allow swapping)
- (decision) Connector Architecture: Strategy/Plugin pattern via abstract BaseJobConnector (authenticate_session, search_jobs, fetch_job_details, prepare_application) with isolated Playwright scrapers per provider (LinkedIn, Jobteaser for MVP)
- (decision) PDF Generation: HTML/CSS template rendered to PDF via Playwright page.pdf() as baseline, evaluated during implementation for output fidelity
- (decision) Application State Machine: Strict finite state transitions (DISCOVERED -> REVIEWING -> READY -> SUBMITTED -> INTERVIEW -> OFFER/REJECTED). Transitions to SUBMITTED require prior READY and explicit human validation. 5-second undo grace period managed in frontend optimistic state before emitting API call.
- (decision) Security & Local Storage: Database and encrypted session tokens isolated in user directory ~/.arcapply/ (arcapply.db and sessions.enc); API keys loaded from local .env or secure local config
