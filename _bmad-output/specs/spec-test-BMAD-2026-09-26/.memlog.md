- (direction) User selected guided mode to validate kernel fields one by one
- (decision) Validated Why: ArcApply resolves the critical asymmetry in PFE internship search (Jan 2027, France/Tunisia), cutting application time from 40min to under 3min via verified Master Profile adaptation, deterministic ATS scoring, authentic cover letter, and human-in-the-loop validation.
- (capability) CAP-1: Master Profile Management & Immutability - User can manage complete personal profile as single source of truth; generation blocked if incomplete.
- (capability) CAP-2: Automated Multi-Platform Job Ingestion - Aggregate PFE offers from LinkedIn and Jobteaser into real-time radar feed with full metadata.
- (capability) CAP-3: Deterministic ATS Matching & Gap Analysis - Match job post against Master Profile to compute percentage score and list exact/missing skills without extrapolation.
- (capability) CAP-4: Zero-Hallucination Tailored CV & PDF Generation - Compile ATS-compliant single-page PDF reordering verified profile items with zero fabricated claims.
- (capability) CAP-5: Natural Tone Cover Letter Synthesis - Generate tailored cover letter in sober, authentic engineer voice avoiding AI clichés.
- (capability) CAP-6: Human-in-the-Loop Review & Assisted Dispatch - Mirror view inspection, manual overrides, explicit human validation required before dispatch.
- (capability) CAP-7: Application Lifecycle Kanban Tracking - Visual stage-based tracking from discovery to offer/archive with timestamps and telemetry updates.
- (constraint) Anti-hallucination invariant: Generation strictly bounded by Master Profile with zero invented skills or claims.
- (constraint) Human-in-the-loop constraint: No autonomous background submission without explicit per-application human confirmation.
- (constraint) Process decoupling constraint: Next.js frontend and FastAPI engine run in separate processes communicating via REST and SSE.
- (constraint) Sovereign local-first persistence: SQLite at ~/.arcapply/arcapply.db owned solely by engine; no external multi-tenant cloud storage for MVP.
- (constraint) Single-page ATS vector PDF constraint: Compiled PDF must adhere to single-page, non-multi-column ATS-parsable standard.
- (constraint) Connector rate-limiting constraint: Playwright scrapers must enforce randomized jitter and request caps to prevent platform blocks.
- (direction) User updated scope: Cockpit must be mobile-friendly, and an incoming email connector must read/classify recruiter replies (interview invite, rejection) and link them to the matching application.
- (capability) CAP-8: Automated Recruiter Email Ingestion & Status Classification - Connect to user's mailbox, parse recruiter responses (interview, rejection, ack), and auto-link updates to the matching application.
- (constraint) Mobile-friendly responsiveness: The web cockpit must provide a responsive layout usable on mobile browsers for monitoring and status checks.
- (decision) Validated Non-goals: No blind auto-apply, no automated outbound follow-up emails, no 3rd party job boards beyond LinkedIn/Jobteaser for MVP, no heavy ATS browser extension, no multi-tenant cloud architecture.
- (decision) Validated Success Signal: Student prepares and validates tailored application under 3 min on desktop or mobile cockpit, submits it, incoming email connector detects recruiter response and moves card to Interview in Kanban, achieving >15% interview rate for Jan 2027 PFE.
